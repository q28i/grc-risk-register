# CHG-0002: Authentication & Role Permissions Engine

- **Change ID**: CHG-0002
- **Component**: Security, Authentication & RBAC
- **Upstream Relationship**: Simplified Upstream
- **Date**: 2026-08-18

---

## 1. Original Behavior
Upstream authentication relied on Odoo's multi-database selector and complex group ACLs (`res.groups`, `ir.model.access.csv`, `ir.rule`) mixing GRC users with general ERP employees and administrators.

## 2. Problem / Reason
1. Multi-database prompts confuse academic reviewers.
2. The permission hierarchy contained unnecessary roles (HR Officer, Inventory Manager).
3. A student cannot easily explain multi-tier Odoo XML record rules during a quick viva.

## 3. Planned Change
Implement a crisp two-tier Role-Based Access Control (RBAC) engine:
1. **Administrator** (`admin` / `admin123`): Manages users, configures parameters, full CRUD, unarchiving, audit trail inspection.
2. **Risk User** (`analyst` / `analyst123`): Records assets, assesses risks, tracks status, views dashboard and reports.

## 4. Implementation Details
- Built secure token-based session authentication in `auth.py`.
- Passwords hashed using standard salted SHA-256 (`hashlib.pbkdf2_hmac`).
- Role guards enforced on REST API endpoints (`/api/users`, `/api/assets/unarchive`, `/api/audit-logs`).
- Automatic pre-seeding of the two default accounts on database initialization.

## 5. Files Modified / Created
- `Grc Risk Management Code/auth.py`

## 6. Tests Performed
- Unit test for valid credentials login.
- Unit test for invalid password rejection.
- Unit test for role privilege escalation prevention (Risk User attempting administrative action receives 403 Forbidden).
- Session expiration and logout verification.
