# CHG-0008: Feature Visibility Controls, Demo Account, Unauthenticated View & Refresh UX

- **Change ID**: CHG-0008
- **Component**: Feature Governance, Demo Authentication, UI/UX State Management & Persistence
- **Upstream Relationship**: Controlled Feature Availability & Academic Demonstration Interface
- **Date**: 2026-08-18

---

## 1. Original Behavior
- The application supported two roles: `admin` and `analyst`.
- When unauthenticated, a login modal appeared as an overlay over the partially visible dashboard structure.
- All authenticated users had full mutation capabilities for Assets and Risks.
- Feature controls could not be dynamically managed or persisted.
- Refresh button did not provide active spinner feedback.

## 2. Problem / Reason
1. Academic evaluators and demo testers require a safe `demo` account (`demo` / `demo123`) that can view all features but has restricted mutation capabilities.
2. The login page must be a true unauthenticated view (`#unauthenticated-view`) with zero application dashboard content visible behind the login form.
3. Disabled features must remain visible in the UI in a disabled state (`opacity: 0.5`, `cursor: not-allowed`) rather than hidden or replaced with disruptive lock icons.
4. Administrators need a dedicated control interface to toggle feature permissions for the demo user, persisted in the SQLite database (`feature_controls` table).
5. The backend must enforce 403 Forbidden responses if a demo user attempts restricted mutation operations.
6. The dashboard refresh action requires clean micro-interaction feedback (`Refreshing...` with a small spinner).

## 3. Planned Change
1. Update `models.py` `VALID_ROLES` to include `'demo'`.
2. Add `feature_controls` table in SQLite (`database.py`) with automatic schema migration and seed 12 standard feature controls.
3. Pre-seed default `demo` account (`demo` / `demo123`, `role: demo`).
4. Expose `GET /api/feature-controls` and Admin-only `PUT /api/feature-controls` in `app.py`.
5. Add backend 403 Forbidden mutation guards on `POST /api/assets`, `PUT /api/assets/<id>`, `POST /api/assets/<id>/archive`, `POST /api/risks`, `PUT /api/risks/<id>`, `POST /api/risks/<id>/archive` when disabled for `demo` role.
6. Refactor `templates/index.html` and `static/css/style.css` into true `#unauthenticated-view` and `#authenticated-view`.
7. Update `app.js`, `reports.js`, and `dashboard.js` to handle feature permissions, disabled button states, admin feature control form, and refresh button spinner state.
8. Add automated test suite `tests/test_feature_controls.py`.

## 4. Implementation Details
- **Database (`database.py`)**: Added `feature_controls` table, migration handler, pre-seeded 12 controls, and implemented `get_feature_controls()`, `get_feature_controls_dict()`, `is_feature_enabled_for_demo()`, `update_feature_controls()`.
- **Backend API (`app.py`)**: Added `GET /api/feature-controls`, `PUT /api/feature-controls` (Admin only), and enforced 403 mutation guards for demo role.
- **Frontend Presentation (`index.html` & `style.css`)**: Implemented `#unauthenticated-view`, `#card-feature-controls` in profile pane, disabled control styling, and spinner animation.
- **Frontend Logic (`app.js`, `reports.js`, `dashboard.js`)**: Wired permission checks (`App.isActionAllowed()`), table button disabled states, admin feature control persistence, and refresh loading indicator.
- **Automated Tests (`test_feature_controls.py`)**: 7 new integration test cases verifying demo seeding, feature controls CRUD, Admin updates, and 403 demo mutation rejections.
