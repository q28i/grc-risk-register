# CHG-0010: Neutral Unavailable-Feature Notice & UI Language Refinement

- **Change ID**: CHG-0010
- **Component**: User Interface Presentation, Informational Messaging, Error Handlers & Tooltips
- **Upstream Relationship**: Academic Demonstration Presentation & Student Project Realism
- **Date**: 2026-08-19

---

## 1. Original Behavior
- When features or sections were unavailable (such as the recent risks list or mutation buttons), the user interface displayed account-specific restriction notices such as:
  - `"Recent risks list is disabled for this account."`
  - `"Asset creation is disabled for Demo User"`
  - `"Editing disabled for Demo User"`
  - `"Report view is disabled for this account."`
- These notices explicitly communicated artificial role/permission lockdowns to evaluators.

## 2. Problem / Reason
1. Stating that features are "disabled for this account" or "disabled for Demo User" exposes internal demo governance mechanisms and detracts from the impression of a coherent student-built software project.
2. Evaluators and users should see unavailable functionality presented naturally as features under active development rather than artificial role lockdowns.
3. A subtle, general informational notice at the top of the authenticated application content area unobtrusively informs users of unavailable items without interrupting navigation or using disruptive modal alerts.
4. Backend security restrictions (403 Forbidden) must remain strictly enforced while providing neutral, professional development messages.

## 3. Planned Change
1. Add a subtle, flat Material-styled informational notice banner at the top of the authenticated content area (`#dev-notice-banner`):
   `"Some features are currently under development and are temporarily unavailable."`
2. Automatically toggle the notice: displayed when features are governed for standard/demo users, and hidden for unrestricted Administrators.
3. Replace all user-facing tooltip text (`title`), empty state placeholders, and toast notifications across `app.js`, `dashboard.js`, and `reports.js` with neutral development wording:
   - `"Feature currently under development"`
   - `"This feature is currently under development."`
   - `"Search is currently unavailable"`
4. Update backend 403 Forbidden error response messages in `app.py` to: `"This feature is currently under development."`
5. Keep loading states (circular spinners and loading skeletons) distinct from unavailable feature states.

## 4. Implementation Details
- **`templates/index.html`**: Added `#dev-notice-banner` at the top of `#app-container` in the authenticated view. Updated `#card-feature-controls` subtitle to neutral capability phrasing.
- **`static/css/style.css`**: Styled `.dev-notice-banner` and `.dev-notice-icon` with a clean flat Material left-border accent (`border-left: 3px solid var(--primary-purple)`), `#FAFAFA` background, and 14px icon.
- **`static/js/app.js`**: Refactored all tooltips, error container texts, empty table states, and toast notifications to neutral phrases. Added banner visibility logic in `updateUserUI()`.
- **`static/js/dashboard.js`**: Replaced `"Recent risks list is disabled for this account."` with `"Feature currently under development."` and updated refresh button tooltip.
- **`static/js/reports.js`**: Updated export/print tooltips and table fallback text to neutral development notices.
- **`app.py`**: Updated REST API mutation 403 error strings to `"This feature is currently under development."`.
- **`database.py`**: Updated `DEFAULT_FEATURE_CONTROLS` descriptions to clean capability descriptions.
