# CHG-0003: Unified Asset Inventory & Safe Archiving

- **Change ID**: CHG-0003
- **Component**: Asset Management Engine
- **Upstream Relationship**: Simplified Upstream
- **Date**: 2026-08-18

---

## 1. Original Behavior
Assets were scattered across 6 disparate models: `data.inventory`, `it.inventory`, `it.component`, `tcp.udp.ports`, `business.process`, and `suppliers.management`. Creating a data asset required configuring RPO/RTO time units, retention periods, disruption hours, port mappings, and process references.

## 2. Problem / Reason
1. High cognitive overhead for beginner students.
2. Form validation was cumbersome with numerous foreign key constraints.
3. Excessive fields (e.g. TCP port numbers) diverted focus from the primary goal: understanding cybersecurity risk associated with organizational assets.

## 3. Planned Change
Consolidate asset management into a unified, high-cohesion `Asset` entity adhering to NIST Cybersecurity Framework (CSF) asset types:
- **Asset ID**: Auto-generated sequential code (`AST-001`, `AST-002`, ...).
- **Name**: Clear descriptive name.
- **Description**: What the asset does or contains.
- **Type**: Taxonomy (`Data`, `System`, `Device`, `Service`).
- **Owner**: Person/department accountable for security.
- **Importance**: Criticality rating (`Low`, `Medium`, `High`).
- **Active**: Boolean flag enabling non-destructive soft-delete / archiving.

## 4. Implementation Details
- Created SQLite table `assets` with indexing on `asset_id` and `active`.
- Added validation for required fields (`name`, `type`, `owner`, `importance`).
- Built safe archive/restore workflows in `database.py` and UI controllers.
- Integrated asset selection dropdown into the Risk creation form.

- Asset validation rejection on missing name or invalid type.
- Asset archiving (verified archived asset is excluded from active register).
- Unarchive permission restriction (only Administrator can restore).
