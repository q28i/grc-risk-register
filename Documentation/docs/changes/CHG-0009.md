# CHG-0009: Final Demo Control Refinement, Granular Feature Matrix & Data Loading State

- **Change ID**: CHG-0009
- **Component**: Authentication UI, Granular Governance Engine, Dynamic Loading Transitions & RBAC Mutation Guards
- **Upstream Relationship**: Controlled Evaluator Experience & Fine-Grained Action Authorization
- **Date**: 2026-08-18

---

## 1. Original Behavior
1. The login page contained a "Quick Sign In" section with helper buttons pre-filling `admin` and `demo` accounts with visible plaintext credentials.
2. Feature controls only had 12 coarse-grained keys across 3 categories.
3. When the dashboard refresh button was clicked, only the button text changed to "Refreshing...", while all existing numbers, heatmaps, and charts remained fully visible without transitioning into an active data loading state.

## 2. Problem / Reason
1. Exposing credentials or quick-login buttons on the login page violates student/academic realism and cybersecurity hygiene.
2. Administrators require granular, per-action controls across all 6 core functional areas (**Dashboard**, **Assets**, **Risks**, **Reports**, **Profile / Audit**, **Administration**) to independently govern what the Demo User can perform.
3. A realistic dashboard refresh must visibly indicate that live data is currently being fetched (KPI numbers display loading placeholders, the 3x3 heatmap cells transition to loading indicators, distribution progress bars reset, and the recent risks table displays loading feedback).
4. Disabled features must remain visible in the UI with standard disabled styling (`opacity: 0.5`, `cursor: not-allowed`) rather than being removed or decorated with distracting "locked" / "coming soon" badges.
5. Server-side mutation endpoints must enforce 403 Forbidden rejections for restricted demo requests while Administrator accounts always maintain full unrestricted access.

## 3. Planned Change
1. **Remove Quick Sign-In**: Remove all quick login buttons, credential labels, and hints from `templates/index.html`, `static/css/style.css`, and `static/js/app.js`.
2. **Granular Feature Controls**: Expand `DEFAULT_FEATURE_CONTROLS` in `database.py` to 29 fine-grained actions organized into 6 distinct categories:
   - **Dashboard**: `dashboard_view`, `dashboard_refresh`, `dashboard_matrix_view`, `dashboard_distribution_view`, `dashboard_recent_view`
   - **Assets**: `asset_view`, `asset_search`, `asset_add`, `asset_edit`, `asset_archive`, `asset_show_archived`, `asset_filter`
   - **Risks**: `risk_view`, `risk_search`, `risk_add`, `risk_edit`, `risk_archive`, `risk_status_change`, `risk_show_archived`, `risk_filter`, `risk_view_details`
   - **Reports**: `report_view`, `report_print`, `report_export_csv`
   - **Profile / Audit**: `profile_view`, `audit_view`
   - **Administration**: `admin_fc_view`, `admin_fc_modify`, `admin_users_view`
3. **Data Loading States**: Implement explicit loading placeholders in `dashboard.js`, `reports.js`, `app.js`, and `style.css` (KPI loading placeholders, 3x3 heatmap skeleton cells with spinners, table loading rows, and progress reset).
4. **Automated & Live Verification**: Update `test_feature_controls.py` and run full regression suites.

## 4. Implementation Details
- **`database.py`**: Configured 29 default feature controls in `DEFAULT_FEATURE_CONTROLS`, updated `init_db()` to seed new keys without overwriting administrator custom settings, and sorted `get_feature_controls()` by category hierarchy.
- **`templates/index.html`**: Completely eliminated `.quick-login-box` from `#unauthenticated-view` and expanded the administrator feature controls form in `#pane-profile` into a 6-category grid.
- **`static/css/style.css`**: Removed quick-login classes, added loading placeholder styles (`.loading-placeholder`, `.loading-fade`, `.cell-loading`), and styled a responsive 3-column / 2-column feature controls grid.
- **`static/js/dashboard.js`**: Added `setLoadingState()` and updated `loadDashboard()` to clear old values into loading states upon refresh and render fresh metrics upon response.
- **`static/js/app.js`**: Removed quick-login event bindings, wired granular permission checks for search, filters, modals, tables, and admin feature control saving.
- **`static/js/reports.js`**: Added loading states for report KPIs and table generation.
- **`tests/test_feature_controls.py`**: Added test cases for 29 granular controls, 6 categories, login page cleanliness, and 403 mutation guards.
